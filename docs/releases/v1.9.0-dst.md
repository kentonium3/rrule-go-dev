# v1.9.0: civil-time recurrence corrections

Recurrence generation now follows RFC 5545 sections 3.3.5 and 3.3.10 across timezone transitions for every frequency, YEARLY through SECONDLY. Generated nonexistent local times are skipped before COUNT and BYSETPOS are applied. Repeated local times yield their first occurrence. Positive and negative BYSETPOS positions are counted after gaps have been removed; skipped positions do not consume COUNT. Iterator, All, Before, After, Between and Set observe the same occurrences and inclusive UNTIL boundary. BY selectors retain their wall-clock meaning, including across Lord Howe's half-hour shifts.

These corrections intentionally change transition-day results for existing schedules, including daily and coarser rules. Sydney HOURLY from 2022-10-02 midnight now yields 00:00, 01:00 AEST, then 03:00, 04:00, 05:00, 06:00 AEDT for COUNT=6. Sydney's 2023-04-02 fold yields 02:00 AEDT once, then 03:00 AEST. A daily 02:30 schedule skips a generated spring-gap date rather than moving it to 03:30.

An explicit parsed DTSTART in a gap is interpreted with the offset before the transition, as RFC 5545 section 3.3.5 requires. Its first resolved physical instant counts once when selected; following candidates retain the original nominal civil cadence. For example Sydney DTSTART 2022-10-02 02:30 resolves to 03:30 AEDT, then a DAILY rule resumes at 02:30 on subsequent dates. A parsed ambiguous DTSTART selects the first offset. A programmatically supplied time.Time is authoritative: a constructor or public DTStart setter given the later fold instant includes that exact first instant once. A public time-only setter replaces parsed nominal semantics. When a gap anchor overlaps later generated civil values, duplicate or earlier physical instants are suppressed without consuming COUNT. If the same-period normal timeset already represents that anchor instant, it contributes only one position before BYSETPOS selection; later distinct positions and out-of-range positions are computed from that unique set.

ROption now contains private immutable parsing metadata. Existing exported fields, keyed literals, functions and method signatures remain available, with no new dependency. This is a source compatibility exception explicitly approved for target v1.9.0: external positional ROption literals that formerly compiled must migrate to keyed literals, for example `ROption{Freq: DAILY, Dtstart: start, Count: 3}`. The minor version label does not make positional literals compatible. Option value copies preserve metadata; replacing one public time invalidates only that part, including when the new time has the same instant in a different *time.Location. Supplied location pointers are retained exactly, including custom FixedZone and TZif locations whose names resemble IANA identifiers.

The resolver uses bounded day-level timezone lookups, supports the verified New York, Sydney and Lord Howe transitions, and preserves arithmetic BYSETPOS selection on regular periods. It does not claim support for arbitrary historical timezone discontinuities or rapidly repeated transitions. The existing UTC short-UNTIL termination bound is retained. Go 1.16 remains supported.

The Sydney transition scenarios and ideas retain useful fixtures from [teambition/rrule-go PR 66](https://github.com/teambition/rrule-go/pull/66), with expected UTC instants independently re-derived from RFC 5545. The elapsed-time algorithm and double-fold expectations from that proposal are not used. Existing MIT attribution and README modified-copy notice remain unchanged. Contributor fix 76c646d is inherited baseline; this change does not assess or extend its duplicate-selector work.

The reusable compatibility driver and fixed corpus are in `docs/repro/05-07-backlog/golden/`; usage is documented at the top of its main.go. The corpus records source provenance, individually skipped dynamic expressions, all-frequency transition samples, and per-row RFC classifications with exact expected output hashes.
